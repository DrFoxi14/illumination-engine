# Architecture

## 1. System boundary

Illumination Engine is a hybrid procedural character framework with Blender as its sole 3D authoring and rendering source.

- **Blender** owns editable geometry, materials, rigging, simulation, scene assembly, and final rendering.
- **Python** owns deterministic configuration, custom geometry generation, orchestration, and validation through `bpy`.
- **glTF/GLB** is the future exchange boundary for supported meshes, materials, skinning, morph targets, and animation clips.
- **Three.js / React Three Fiber** is a downstream viewer for exported assets. It does not author a competing character model.

P1 does not import or depend on a third-party humanoid base mesh. The character is assembled from original parametric geometry generated by the project.

## 2. Character data flow

1. A versioned JSON character specification is loaded and validated by the pure-Python core.
2. Blender creates the character collections and material palette.
3. Parametric lofts create the head, torso, and clothing volumes.
4. Swept quad surfaces create limbs, fingers, facial contours, sleeves, socks, and hair clumps.
5. Dedicated facial components create eye sockets, eyeballs, irises, pupils, lids, brows, nose, mouth, and ears.
6. Blender builds a studio scene, renders silhouette passes and a color preview, and saves the editable `.blend` project.
7. Later milestones add production topology, shape keys, rigging, animation, GLB export, and the Three.js viewer.

## 3. Geometry factory

The Blender geometry layer provides:
- **Loft surfaces:** horizontally sampled elliptical profiles with Catmull-Rom interpolation.
- **Swept surfaces:** tapered cross-sections following 3D control curves with a moving local frame.
- **Ellipsoid meshes:** generated directly from UV coordinates for eyes, ears, and other local forms.
- **Material factory:** converts sRGB palette values to linear shader inputs and creates Principled materials.

These are building blocks for art-directed forms, not claims of automatic film-quality sculpting. They deliberately create editable meshes so geometry can be revised as the character is reviewed.

## 4. Runtime separation

The Python package must remain importable without Blender. Modules that use `bpy`, `bmesh`, or `mathutils` live behind the Blender-specific runtime boundary and only execute inside Blender's bundled Python runtime.

CI validates pure-Python configuration, source syntax, lint, and deterministic rules. It does not run Blender renders.

## 5. Asset interchange

GLB is the planned web-delivery format. The intended contract includes supported mesh/material properties, skeletal skinning, animation clips, morph targets, and stable asset metadata.

Not every Blender feature maps perfectly to glTF. Procedural hair, advanced shader networks, cloth simulation, and Blender-specific render effects may need to be baked or represented by simplified preview assets. The Blender project remains authoritative.

## 6. Quality gates

- **Code:** lint, unit tests, and compile checks.
- **Geometry:** inspect normals, intersections, continuity, profile spacing, and mesh validity.
- **Face:** inspect eye placement, eyelid arcs, brow expression, nose/mouth proportions, and face silhouette.
- **Visual:** render front, side, three-quarter, and close-up views; review the silhouette, materials, hair, and clothing.
- **Deformation:** later test the face and body under actual animation before accepting the rigs.

A green CI run proves code invariants, not that a character has studio-quality appeal. P1 requires local Blender renders and human visual review.

## 7. Repository boundaries

- `engine/core/`: Blender-independent configuration and validation.
- `engine/blender/`: custom mesh generation and scene construction.
- `characters/`: versioned character specifications.
- `viewer/`: future Three.js presentation client.
- `scripts/`: local build, validation, and render commands.
- `tests/`: tests that run without Blender wherever possible.
- `.github/workflows/`: continuous integration.

Generated renders and temporary build output are not committed to Git.
